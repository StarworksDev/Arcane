# Arcane 1.0 feature inventory: everything from now to 1.0

**Date:** 2026-10-05. **Companion to:** `2026-10-05-arcane-1.0-roadmap.md` (the D-rows, the schedule and the decisions). **Binding principle:** one engine, two games (roadmap §2.0).

**Legend:**
- **[A]** Aphelyon, the F2P gacha. It ships first and gates 1.0.
- **[S]** the space game.
- **[A+S]** both.
- *seam* means 1.0 ships the interface plus a first version; the full feature layers on after 1.0 without architectural change.
- ★ marks items that were not in roadmap rows D1-D24 when this list was compiled; they become D25+.

## 0. In flight / owed (finish first)

- **The settings arc:**
  - **Remaining tasks:** S3-13 → S3-GATE; S2-7..S2-GATE; S4 (theme editor and presets, keyboard-shortcut editor with conflict highlighting, fonts and UI scale, layouts); the S5-2 user review; S6 (the sweep exposing every tunable); S7 (player settings, server admin console, remote cvar service, audit).
  - **Its owed fixes:** settings archive writes that report failure, and the rest of `carry/S3-GATE.md`.
- **Input seam:** the engine publishes input and fixed-step time to systems as registry resources.

- **Manifold2D re-vendor + `SetExecutor` wiring:** physics multithreading actually on.
- **Crash-window plan 3:** autosave and recovery.
- **Hygiene:**
  - a platform abstraction alias header + `_WIN32` sweep;
  - a unified stdout/log output policy;
  - arcbuild II (`Arcane::Process`, `--engine`, the DebugGame config);
  - a written threading policy.
- **Linux port + CI:** a cloud session, issue T3mps/Arcane#1, branch `linux/port`.

## 0.5 Next arc after the settings arc

- **Servitor (remote-control CLI, formerly `arc`), jack-in automation (D27)** [A+S]: attach to or launch a running editor/runtime/headless host and fully pilot it.
  - **query:** live ECS, scene, logs, frame stats;
  - **act:** editor actions by name (undoable), cvars, play/step;
  - **see:** screenshots, the ImGui widget tree, golden diffs;
  - **output:** JSON;
  - **security:** local-only, a token, off in Dist.

  It is NOT MCP; the model is Unity's CLI. It runs ahead of the render foundation because it automates the desk-check gates.

## 1. Core foundations

- **Astra 1.0 hardening (D25)** [A+S], upstream-first:
  - **set before 1.0 (ABI-wide):** 64-bit entities and a component cap above 128;
  - **remap and snapshots:** visitor + `RemapEntities` + clone; per-entity snapshot/restore; cross-registry moves;
  - **change tracking:** `Removed<T>`; an on-set observer; a tick wrap clamp; portable type hashes; per-field dirty bits;
  - **FOUNDATIONAL:** a unified `View` reading table / sparse / universal (always-present components like `Identity`) / relationship storages; sparse and universal are already planned in Astra, each kept separate (relationships are never encoded as components);
    - Conditions for the relationship storage: declared scheduler access; change ticks for reparent/link edits; first-class in snapshot/remap/replication; a churn + ancestor-walk benchmark at space-game scale before the work starts.
  - **in Arcane:** real parallel systems.

- **Large-world precision** [S, foundational]: 64-bit world positions, camera-relative rendering, origin rebasing. It lands before the render and physics arcs touch transforms.
- **Loading and streaming** [A+S]: async asset loading, an async I/O lane, level/cell streaming.
- **Save/load** [A+S]: game-state serialization with versioning and migration.
- **Persistence seam** [A+S] over the Postgres services stack (Aphelyon accounts; space-game bases, inventories, seasons).
- **Jobs:**
  - a render thread;
  - parallel command recording;
  - awaitable tasks;
  - priorities.
- **Memory:** an allocator seam + mimalloc, with budgets.
- **Profiling:**
  - Tracy engine-wide;
  - frame-budget gates;
  - an ECS inspector panel;
  - live query.

## 2. Rendering

- **Core pipeline:**
  - clustered deferred;
  - PBR;
  - the unified Surface material domain (2D through the 3D renderer; key for Aphelyon's isometric view).
- **Lighting:**
  - cascaded sun shadows + local-light shadows;
  - GTAO;
  - SSR + reflection probes;
  - baked GI.
- **Post + upscaling:**
  - bloom, exposure, tonemap, color-grading LUTs;
  - TAA + the upscaler interface with FSR 3.
- ★ **Stylized rendering toolkit** [A+S]: outlines, ramp/toon lighting options, rim light, painterly shading (the Deadlock/Borderlands look; anime gacha styling).
- ★ **Decals** [A+S]: bullet holes, damage, base raid marks, set dressing.
- **Scale:**
  - LOD + HLOD;
  - instancing;
  - finish GPU-driven culling.
- **Environment:**
  - sky + atmosphere scattering, fog;
  - space rendering: starfield, the planet from orbit.
- **Terrain:** the terrain-provider seam + a demo cube-sphere planet [S]; heightfield/grid terrain for Aphelyon's overworld [A].
- **Editor:** an interactive material preview viewport.

- **Animation graph:**

## Deliberately NOT in 1.0 (each layers on a 1.0 seam)

- dynamic server meshing;
- the production spherical planet;
- walkable ship interiors;
- guild ships;
- voice chat;
- consoles;
- mobile;
- VR (OpenXR on D3D12 and Vulkan), PC VR first. 1.0 keeps it possible: every render-side design stays multi-view-aware, never assuming one camera per frame. F5's per-view extract and render origins carry the two eye views. D1's clustered light grid is built once, so a forward + MSAA VR path can reuse it. Input goes through the action-based input seam that OpenXR actions map onto. The test device is a Meta Quest 3 over Quest Link / Air Link to the PC. (User, 2026-10-15.)

## Effect on the date

The ★ items add roughly 8-12 arcs beyond D1-D24. The biggest are the ability framework, the timeline, data tables, prefabs, FBX import + retargeting, and Steamworks / patching. Honest 1.0 is **February-March 2027**, unless some move post-1.0. Patching and telemetry could land before Aphelyon's launch rather than at 1.0. The ★ items fold into the roadmap as D25+, and the month-by-month schedule gets rebuilt once the settings arc closes.
